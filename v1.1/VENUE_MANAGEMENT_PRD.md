# 1. 背景与目标

## 1.1 背景

建筑物管理应用用于维护学校建筑、操场及其扩展档案，并向教育局提供跨学校只读查询和学校统计能力。当前版本为静态高保真交互原型，学校端与教育局端使用独立入口、菜单和页面，通过同一浏览器的 localStorage 共享演示数据。

当前业务结构如下：

- 学校端菜单包含建筑管理、操场管理和修改记录。
- 教育局端菜单包含学校统计、建筑管理和操场管理；默认仍进入建筑管理。
- 学校端维护本校档案；教育局端只读查看管理范围内数据。
- 学校面积概况为学校级独立数据，不与建筑或操场档案汇总关联。
- 一个操场可维护多个同类型或不同类型的场地模块；改造记录归属于具体场地模块。
- 建筑、操场基础档案与附件、专项设施、场地模块和器材分别持久化，再按档案 ID 合并展示。

## 1.2 目标

- 支持学校完整维护学校面积概况、建筑、操场、专项设施、维修记录、场地模块、模块改造记录、器材和附件。
- 支持教育局查看学校端最新建筑和操场档案，并按学校汇总八项统计数据。
- 保证独立 Markdown PRD、页面内 PRD、表单、列表、详情和发布断言使用一致口径。
- 通过前端模拟数据展示完整可交互流程，不扩展真实后端、数据库或生产级权限。

# 2. 用户与使用场景

## 2.1 学校端用户

| 用户 | 数据范围 | 核心场景 |
|---|---|---|
| 学校建筑物管理员 | 当前学校 | 独立填报学校整体、租赁和自有面积 |
| 学校建筑物管理员 | 当前学校 | 新增、查看、编辑和删除建筑、操场档案 |
| 学校建筑物管理员 | 当前学校 | 维护建筑专项设施、维修记录和附件 |
| 学校建筑物管理员 | 当前学校 | 维护操场场地模块、模块改造记录、器材和附件 |
| 学校项目工作人员 | 当前学校 | 在项目申请中关联本校建筑或操场 |

## 2.2 教育局端用户

| 用户 | 数据范围 | 核心场景 |
|---|---|---|
| 教育局建筑物管理人员 | 管理范围内学校 | 按学校名称查看学校面积、建筑和操场汇总统计 |
| 教育局建筑物管理人员 | 管理范围内学校 | 导出当前学校名称筛选后的全部学校统计结果 |
| 教育局建筑物管理人员 | 管理范围内学校 | 筛选并只读查看建筑、操场及扩展档案 |

## 2.3 典型场景

1. 学校首次进入建筑管理，面积概况显示未登记；管理员独立填写三项学校面积。
2. 学校新增教学楼，填写建筑面积、层数、结构、选填鉴定等级和鉴定日期，并维护专项设施及维修记录。
3. 学校新增操场后，为同一操场登记多个田径场、足球场、篮球场、户外草坪等场地模块。
4. 学校在具体场地模块中登记改造记录，维护操场器材和附件。
5. 教育局刷新或切换菜单后读取学校端最新档案，并在学校统计中查看数量和面积汇总。
6. 教育局筛选学校名称，分页核对结果，并导出当前筛选范围内的全部学校统计数据。

# 3. 需求范围

## 3.1 In Scope

- 学校端建筑管理、操场管理、修改记录和学校面积概况。
- 教育局端学校统计、建筑管理和操场管理。
- 建筑、操场基础档案的 localStorage 持久化和双端共享。
- 建筑专项设施、维修记录和附件资料。
- 操场场地模块、分类扩展字段、模块改造记录、器材和附件资料。
- 学校统计八字段口径、模糊筛选、每页 10 条分页和 XLSX 导出。
- 一键重置演示数据及旧操场草坪、旧改造记录兼容迁移。

## 3.2 Out of Scope

- 校区管理、空间测绘、正式统计口径和土地权证管理。
- 教育局端编辑学校面积、建筑、操场或扩展档案。
- 服务端 Excel 生成、导出记录、排序、分页条数切换和统计钻取。
- 真实登录、生产级权限、后端接口、数据库、Prisma 和文件服务器。
- 维修审批、改造审批、隐患整改、自动提醒和正式审计。

## 4.1 学校面积概况

| 字段 | 控件类型 | 必填 | 规则 | 存储字段 |
|---|---|---:|---|---|
| 学校整体面积 | 数字输入 | 是 | 大于 0，最多两位小数 | `schoolAreaProfiles[school].totalArea` |
| 租赁面积 | 数字输入 | 是 | 大于等于 0，最多两位小数 | `schoolAreaProfiles[school].leasedArea` |
| 自有面积 | 数字输入 | 是 | 大于等于 0，最多两位小数 | `schoolAreaProfiles[school].ownedArea` |
| 更新时间 | 系统生成 | 否 | 精确到秒，不在概况卡片展示 | `updatedAt` |

面积概况使用独立存储键 `edu-prototype-v1.1:education-school-area-profiles-v2`。默认无记录时显示“暂未登记学校面积概况”，编辑弹窗不重复展示学校名称和说明文字。

| 防水 | 屋面类型、防水部位、防水材料、防水等级、防水面积 |

# 5. 核心流程与交互说明

## 5.1 学校面积概况

1. 学校用户进入建筑管理，查看独立面积概况模块。
2. 无数据时点击“编辑”，填写学校整体、租赁和自有面积。
3. 系统校验数值；分项之和不等于整体面积时显示差额提示但不阻止保存。
4. 保存独立记录并生成“编辑学校面积概况”修改记录，不改变建筑、操场或项目数据。

## 5.2 学校端建筑维护

1. 学校用户新增或编辑建筑基础信息并保存至统一基础档案存储。
2. 用户进入详情，在专项设施中维护子档案和维修记录，在附件资料中维护附件元数据。
3. 删除建筑前二次确认；删除后同步清理对应扩展存储并写入操作记录。

## 5.3 学校端操场维护

1. 学校用户新增或编辑操场基础信息。
2. 用户进入操场详情，在“场地模块”中新增多个用途模块。
3. 用户在模块详情中查看、编辑、删除模块或登记模块改造记录。
4. 用户在“器材信息”“附件资料”中维护器材和附件。
5. 删除操场后同步清理场地模块、器材和附件数据。

## 5.4 教育局只读查看与统计

1. 教育局用户进入建筑物管理应用，默认进入建筑管理。
2. 用户可进入学校统计，输入学校名称关键词并查看每页 10 所学校的结果。
3. 系统按统一基础档案和独立面积概况计算八项字段。
4. 用户点击导出，生成当前筛选全部结果的 `学校建筑统计.xlsx`。
5. 用户进入建筑或操场管理，筛选学校并只读查看基础信息和扩展档案。

## 5.5 跨端同步与重置

1. 学校端保存建筑或操场后立即写入统一 localStorage。
2. 同一页面切换到教育局端时重新读取当前数据；不同标签页通过刷新读取。
3. 一键重置恢复预置建筑、操场和扩展数据，学校面积恢复未登记。

# 6. 异常场景与边界条件

| 场景 | 处理规则 |
|---|---|
| 学校面积为空、为负数或超过两位小数 | 阻止保存并显示错误 |
| 学校面积分项之和与整体面积不一致 | 显示差额提示，允许保存 |
| 建筑或操场名称为空、长度不合法或同校重名 | 阻止保存 |
| 面积小于等于 0或超过两位小数 | 阻止保存 |
| 年份超出 1800—当前年份后一年的范围 | 阻止保存 |
| 建筑层数不是 1—199 整数 | 阻止保存 |
| 鉴定等级超过 20 个字符 | 阻止保存 |
| 地面材质为“其他”但未填写材质名称 | 阻止保存模块 |
| 场地模块分类数量字段不是有效整数 | 阻止保存模块 |
| 模块面积合计与操场总面积不一致 | 允许保存，不展示差额说明 |
| 删除场地模块 | 二次确认；同步删除其内部改造记录并写入模拟日志 |
| 学校统计筛选无结果 | 显示空状态并禁用导出 |
| 学校统计页码越界 | 修正到最后一个有效页 |
| Excel 生成失败 | 提示“导出失败，请重试”，不修改业务数据 |
| 教育局用户尝试写操作 | 页面不提供写入入口 |
| localStorage 缺失 | 使用预置场景或未登记空状态 |
| 旧户外草坪或操场级改造数据 | 执行幂等迁移，避免重复生成模块 |

# 7. 数据口径与埋点需求

## 7.1 数据与统计口径

| 数据 | 存储或计算口径 |
|---|---|
| 建筑、操场基础档案 | `edu-prototype-v1.1:education-venue-records-v1` |
| 学校面积概况 | `edu-prototype-v1.1:education-school-area-profiles-v2` |
| 附件 | `edu-prototype-v1.1:education-venue-attachments-v1` |
| 建筑/操场数量 | 对应学校、对应类型的现存基础档案条目数 |
| 建筑/操场总面积 | 对应学校、对应类型的现存档案 `area` 之和 |
| 场地模块面积 | 模块自身独立填报，不反推操场总面积 |
| 更新时间 | 基础档案或扩展数据发生对应变更时生成的客户端演示时间 |

## 7.2 埋点需求

当前原型以修改记录和模块内部模拟日志替代正式埋点。正式系统预留页面进入、筛选、翻页、导出、档案新增/编辑/删除、面积概况编辑、模块维护、维修记录、器材和附件操作事件；当前版本不接入正式采集平台。

# 8. 风险、依赖与限制

- 数据仅保存在同一浏览器 localStorage，不支持跨设备或跨浏览器同步。
- 不监听跨标签页实时变化；刷新或切换菜单后读取最新数据。
- 教育局只读和学校数据范围为前端演示约束，不构成生产级权限控制。
- XLSX 由前端原生 JavaScript 离线生成，不包含服务端文件、导出记录或审计。
- 附件不保存二进制，刷新后临时预览地址不保证可继续使用。
- 操场模块面积不等于测绘面积，不作为正式空间统计依据。
- 页面字段变化必须同步本 PRD、产品需求建筑管理章节、页面内 PRD和发布断言。

# 9. 验收标准

## 9.1 学校端

- 建筑管理展示独立学校面积概况，默认无数据，可单独编辑并产生差额提示和修改记录。
- 建筑、操场新增、编辑、删除后刷新仍保留，且不会相互修改独立面积数据。
- 建筑详情可维护八类专项设施、维修记录和附件。
- 操场详情标签为基础信息、场地模块、器材信息、附件资料，不存在操场级独立改造记录标签。
- 同一操场可新增多个同类型模块；“其他”模块不显示自定义类型名称。
- 模块改造记录归属于具体模块，删除模块同步移除其改造记录。

## 9.2 教育局端

- 菜单中“学校统计”位于“建筑管理”上方，默认页面仍为建筑管理。
- 学校统计固定展示八列，字段来源和计算结果符合第 4.7 节。
- 每页 10 所学校，筛选、翻页、空状态和页码修正正确。
- 导出包含当前筛选后的全部结果，文件名、工作表名、数值格式和空值处理正确。
- 教育局建筑、操场页面不显示学校面积概况和任何新增、编辑、删除入口。
- 学校端变更后，教育局刷新或切换页面可读取最新数据。
