# 1. 背景与目标

## 1.1 背景

建筑物管理应用用于维护学校建筑、操场及其扩展档案，并向教育局提供跨学校只读查询和学校统计能力。当前版本为静态高保真交互原型，学校端与教育局端使用独立入口、菜单和页面，通过同一浏览器的 localStorage 共享演示数据。

当前业务结构如下：

- 学校端菜单包含建筑管理、操场管理和操作日志。
- 教育局端菜单包含学校统计、建筑管理、操场管理和操作日志；默认仍进入建筑管理。
- 学校端维护本校档案；教育局端只读查看管理范围内数据。
- 学校面积概况为学校级独立数据，不与建筑或操场档案汇总关联。
- 一个操场可维护多个同类型或不同类型的场地模块；改造记录归属于具体场地模块。
- 建筑、操场基础档案与附件、专项设施、场地模块和器材分别持久化，再按档案 ID 合并展示；成功数据变更统一写入独立操作日志集合。

## 1.2 目标

- 支持学校完整维护学校面积概况、建筑、操场、专项设施、维修记录、场地模块、模块改造记录、器材和附件。
- 支持教育局查看学校端最新建筑和操场档案，并按学校汇总八项统计数据。
- 保证独立 Markdown PRD、页面内 PRD、表单、列表、详情和发布断言使用一致口径。
- 覆盖建筑管理全部成功数据变更，保留操作对象、所属学校、上级场地及业务数据来源快照。
- 通过前端模拟数据展示完整可交互流程，不扩展真实后端、数据库或生产级权限。

# 2. 用户与使用场景

## 2.1 学校端用户

| 用户 | 数据范围 | 核心场景 |
|---|---|---|
| 学校建筑物管理员 | 当前学校 | 独立填报学校整体、租赁和自有面积 |
| 学校建筑物管理员 | 当前学校 | 新增、查看、编辑和删除建筑、操场档案 |
| 学校建筑物管理员 | 当前学校 | 维护建筑专项设施、维修记录和附件 |
| 学校建筑物管理员 | 当前学校 | 维护操场场地模块、模块改造记录、器材和附件 |
| 学校项目工作人员 | 当前学校 | 在项目申请中关联本校建筑或操场 |

## 2.2 教育局端用户

| 用户 | 数据范围 | 核心场景 |
|---|---|---|
| 教育局建筑物管理人员 | 管理范围内学校 | 按学校名称查看学校面积、建筑和操场汇总统计 |
| 教育局建筑物管理人员 | 管理范围内学校 | 导出当前学校名称筛选后的全部学校统计结果 |
| 教育局建筑物管理人员 | 管理范围内学校 | 筛选并只读查看建筑、操场及扩展档案 |

## 2.3 典型场景

1. 学校首次进入建筑管理，面积概况显示未登记；管理员独立填写三项学校面积。
2. 学校新增教学楼，填写建筑面积、层数、结构、选填鉴定等级和鉴定日期，并维护专项设施及维修记录。
3. 学校新增操场后，为同一操场登记多个田径场、足球场、篮球场、户外草坪等场地模块。
4. 学校在具体场地模块中登记改造记录，维护操场器材和附件。
5. 教育局刷新或切换菜单后读取学校端最新档案，并在学校统计中查看数量和面积汇总。
6. 教育局筛选学校名称，分页核对结果，并导出当前筛选范围内的全部学校统计数据。
7. 学校端查看本校全部成功变更日志，教育局端查看管理范围内跨学校日志；删除业务对象后删除日志继续保留。

# 3. 需求范围

## 3.1 In Scope

- 学校端建筑管理、操场管理、操作日志和学校面积概况。
- 教育局端学校统计、建筑管理、操场管理和操作日志。
- 建筑、操场基础档案的 localStorage 持久化和双端共享。
- 建筑专项设施、维修记录和附件资料。
- 操场场地模块、分类扩展字段、模块改造记录、器材和附件资料。
- 建筑、操场、操作日志、专项设施、场地模块和器材信息列表的跨页连续序号及可切换每页条数的真实分页。
- 学校统计八字段口径、模糊筛选、每页 10 条分页和 XLSX 导出。
- 一键重置演示数据及旧操场草坪、旧改造记录兼容迁移。
- 22 类成功写操作的统一日志生成、版本化持久化、旧日志一次性迁移及双端范围隔离。
- V1.1.12 首次加载的一次性操作日志演示场景：通过 28 次真实业务写入生成指定日志，不直接写入伪造日志。

## 3.2 Out of Scope

- 校区管理、空间测绘、正式统计口径和土地权证管理。
- 教育局端编辑学校面积、建筑、操场或扩展档案。
- 服务端 Excel 生成、导出记录、列表自定义排序和统计钻取。
- 真实登录、生产级权限、后端接口、数据库、Prisma 和文件服务器。
- 维修审批、改造审批、隐患整改、自动提醒和正式审计。

## 4.3 建筑专项设施与维修记录

专项设施公共字段为设施类型、档案名称、当前状态、维修状态、最近改造年份、添加时间、更新时间和备注。当前状态为“良好”“需维修”，默认“良好”；维修状态为只读字段并紧跟当前状态展示。没有维修记录时为“未维修”；存在维修记录且当前日期不晚于最新维修日期加保修期限时为“已维修”；超过保修截止日期时为“过保”。改造和更换记录不参与计算，计算结果不写入 localStorage。最近改造年份使用 1900—当前年份后一年度的倒序年份选择器。列表按当前结果连续展示序号，设施类型和当前状态精确筛选，档案名称包含匹配，多个条件按 AND 组合。学校端操作列包含查看、编辑、删除，删除前二次确认并同步删除该设施的维修记录；教育局端仅展示查看。

| 类型 | 专属字段 |
|---|---|
| 门 | 门类型、设置位置、门数量、五金状态 |
| 窗 | 窗户类型、窗框材质、玻璃类型、设置位置、窗数量、五金状态、密封性能 |
| 防水 | 屋面类型、防水部位、防水材料、防水等级、防水面积 |
| 外墙 | 所在位置、外立面材质、保温类型、保温材料、保温厚度 |
| 内墙 | 所在位置、空间类型、墙体类型、墙体基层材料、内墙饰面材料 |
| 卫生间 | 所在位置、卫生间类型、便器类型、建筑面积 |
| 浴室 | 所在位置、浴室类型、淋浴位数量、建筑面积 |
| 消防设施 | 消防设施类别、设置位置、数量、单位 |

防水屋面类型选项为“可上人”“不可上人”。消防设施类别必填，其余专属字段均为选填；填写数量或面积时校验数值范围。维修记录包含日期选择方式填写的维修时间、维修公司、维修内容、保修期限和系统添加时间；保修期限必须从“1个月、3个月、6个月、1年、3年、5年、8年、10年”中选择。历史“2年”按24个月兼容计算，但不作为新增记录选项；历史记录缺少合法保修期限时保持“已维修”，不误判为“过保”。

| 备注 | 多行文本 | 否 | 最多 200 个字符 |

操场基础信息不使用单一面层材质或“是否包含足球场”描述整个操场。详情展示操场总面积、场地模块数、已登记模块面积和用途摘要，不展示模块面积与总面积的差额说明。

## 4.5 操场场地模块

| 字段 | 必填 | 规则或选项 |
|---|---:|---|
| 模块类型 | 是 | 户外草坪、田径场、足球场、篮球场、排球场、网球场、羽毛球场、乒乓球场、其他 |
| 模块名称 | 是 | 非空；同类型允许重复 |
| 面积 | 是 | 大于 0，最多两位小数 |
| 地面材质 | 是 | 塑胶、人工草坪、天然草坪、硅PU、水泥、沥青、木地板、悬浮地板、其他 |
| 其他材质 | 条件必填 | 地面材质选择“其他”时填写 |
| 建造年份 | 否 | 年份下拉；1800—当前年份后一年度，倒序展示 |
| 最近改造年份 | 否 | 年份下拉；1800—当前年份后一年度，倒序展示 |
| 当前状态 | 是 | 良好、需养护、改造中、停用 |
| 添加时间 | 系统生成 | 新增模块时生成，精确到秒 |
| 更新时间 | 系统生成 | 新增、编辑或登记改造记录时生成，精确到秒 |
| 备注 | 否 | 最多 200 个字符 |

分类扩展字段：户外草坪维护灌溉方式；田径场维护跑道数量和跑道规格；足球场维护场地制式和球门数量；篮球场、排球场、网球场、羽毛球场、乒乓球场维护场地规格和场地数量，数量默认 1；“其他”类型不采集自定义类型名称。列表按分页结果展示跨页连续序号，模块类型和当前状态精确筛选，模块名称包含匹配，多个条件按 AND 组合。学校端操作列包含查看、编辑、删除；教育局端仅展示查看。分页仅切分展示数据，查看、编辑和删除继续使用模块记录 ID 定位原始记录。

## 4.6 模块改造记录、器材与附件

| 模块 | 字段 | 必填 | 规则 |
|---|---|---:|---|
| 模块改造记录 | 改造日期、施工单位、改造内容 | 是 | 改造日期使用日期选择器；保存后生成记录时间；归属当前场地模块 |
| 器材信息 | 器材分类、名称、数量、当前状态 | 是 | 数量为正整数；状态为良好、需要维护、停用；列表按分页结果跨页连续编号，操作使用器材记录 ID 定位 |
| 附件资料 | 名称、格式、大小、添加时间 | 否 | 单档案最多 10 个，单个不超过 10MB |

附件支持 PDF、DOC、DOCX、XLS、XLSX、PNG、JPG、JPEG。原型只保存文件元数据和可选临时预览地址，不保存文件二进制。

## 4.7 教育局学校统计

| 字段 | 数据来源与计算方式 | 空值规则 |
|---|---|---|
| 学校名称 | 建筑/操场基础档案与学校面积概况中的学校并集，去重后按名称排序 | 并集为空时显示页面空状态 |
| 学校总面积 | `schoolAreaProfiles[school].totalArea` | 未登记显示“—”，导出留空 |
| 学校租用面积 | `schoolAreaProfiles[school].leasedArea` | 未登记显示“—”，导出留空 |
| 学校自有面积 | `schoolAreaProfiles[school].ownedArea` | 未登记显示“—”，导出留空 |
| 学校建筑数量 | 该学校现存 `BUILDING` 基础档案数量；所有状态计入，已删除不计 | 无档案显示 0 |
| 学校建筑总面积 | 该学校现存建筑 `area` 相加 | 无档案显示 0 |
| 学校操场数量 | 该学校现存 `PLAYGROUND` 基础档案数量；所有状态计入，已删除不计 | 无档案显示 0 |
| 学校操场总面积 | 该学校现存操场 `area` 相加 | 无档案显示 0 |

学校名称支持模糊筛选。默认第 1 页，每页 10 所学校；筛选变化回到第 1 页，数据变化导致页码越界时修正到最后一个有效页。导出包含当前筛选后的全部结果，不受页码影响；文件名为 `学校建筑统计.xlsx`，工作表名为“学校统计”，数量和面积使用数值单元格。

## 4.8 操作日志

运行时操作日志覆盖以下 22 类成功数据变更：

| 业务对象 | 操作范围 | 业务数据来源 |
|---|---|---|
| 建筑档案 | 新增建筑档案、编辑建筑档案、删除建筑档案 | `education-venue-records-v1` |
| 操场档案 | 新增操场档案、编辑操场档案、删除操场档案 | `education-venue-records-v1` |
| 学校面积概况 | 编辑学校面积概况 | `education-school-area-profiles-v2` |
| 专项设施 | 新增专项设施、编辑专项设施、删除专项设施 | `education-building-facilities-v6` |
| 维修记录 | 新增维修记录 | `education-building-facilities-v6` |
| 场地模块 | 新增场地模块、编辑场地模块、删除场地模块 | `education-playground-records-v1` |
| 模块改造记录 | 新增模块改造记录 | `education-playground-records-v1` |
| 器材信息 | 新增器材信息、编辑器材信息、删除器材信息 | `education-playground-records-v1` |
| 建筑附件 | 上传建筑附件、删除建筑附件 | `education-venue-attachments-v1` |
| 操场附件 | 上传操场附件、删除操场附件 | `education-venue-attachments-v1` |

每条日志固定包含 `id`、`action`、`targetType`、`targetId`、`targetName`、`school`、`parentVenueId`、`operator`、`occurredAt`、`sourceKey`。日志在业务数据保存成功后写入 `edu-prototype-v1.1:education-venue-audit-logs-v1`，按操作时间倒序展示。批量上传按每个成功保存的附件分别生成一条所属场地类型对应的日志。日志与业务对象独立持久化，删除建筑、专项设施、场地模块、器材或附件后，对应删除日志继续保留。

页面进入、筛选、分页、详情查看、附件预览、下载、统计导出、校验失败和取消操作不生成操作日志。删除父对象引起的子数据级联清理归入父对象删除日志，不为被级联清理的每条子数据生成额外日志。

V1.1.12 在统一日志演示场景标记不存在时执行一次真实业务写入链路，业务对象与日志使用 `audit-demo-v1112` 前缀建立可验证关联。场景依次完成 5 次新增建筑、3 次编辑建筑、8 次上传建筑附件、3 次删除建筑附件、4 次新增专项设施、3 次新增维修记录和 2 次删除建筑，共 28 次成功变更。每次先保存对应业务数据，再追加日志；日志的所属学校固定为海淀区实验中学、操作人固定为张老师，操作时间按秒递增生成并在列表中倒序展示。场景成功后写入 `edu-prototype-v1.1:education-venue-audit-demo-scenario-v1` 标记，刷新时不得重复执行。原有 3 条默认日志的 ID、内容和数据来源保持不变。

V1.1.13 加载统一日志时，对历史“上传附件／删除附件”执行幂等归类。系统优先通过 `parentVenueId` 匹配现存建筑或操场；父场地已删除时，通过同一对象 ID 的建筑档案或操场档案历史日志判断。可可靠识别时更新为对应的建筑附件或操场附件动作且不新增日志；无法判断时保留原动作名称，不执行猜测性归类。

# 5. 核心流程与交互说明

## 5.1 学校面积概况

1. 学校用户进入建筑管理，查看独立面积概况模块。
2. 无数据时点击“编辑”，填写学校整体、租赁和自有面积。
3. 系统校验数值；分项之和不等于整体面积时显示差额提示但不阻止保存。
4. 保存独立记录并生成“编辑学校面积概况”操作日志，不改变建筑、操场或项目数据。

## 5.2 学校端建筑维护

1. 学校用户新增或编辑建筑基础信息并保存至统一基础档案存储。
2. 用户进入详情，在专项设施中维护子档案和维修记录，在附件资料中维护附件元数据。
3. 用户可按设施类型、档案名称和当前状态组合筛选专项设施；筛选变化回到第 1 页，分页后查看、编辑、删除仍使用原始数据索引定位正确记录。
4. 删除专项设施或建筑前二次确认；删除后同步清理对应维修记录或扩展存储并写入操作记录。

## 5.3 学校端操场维护

1. 学校用户新增或编辑操场基础信息。
2. 用户进入操场详情，在“场地模块”中新增多个用途模块。
3. 用户可按模块类型、模块名称和当前状态组合筛选场地模块；筛选变化回到第 1 页，分页后查看、编辑、删除仍使用记录 ID 定位正确记录。
4. 用户在模块详情中查看、编辑、删除模块或登记模块改造记录。
5. 用户在“器材信息”列表查看跨页连续序号及公共字段；点击查看打开与编辑弹窗同尺寸的纯只读详情弹窗，弹窗不展示说明文案且仅提供关闭操作；学校端可在列表直接编辑或二次确认删除，操作继续使用器材记录 ID；在“附件资料”中维护附件。
6. 删除操场后同步清理场地模块、器材和附件数据。

## 5.4 教育局只读查看与统计

1. 教育局用户进入建筑物管理应用，默认进入建筑管理。
2. 用户可进入学校统计，输入学校名称关键词并查看每页 10 所学校的结果。
3. 系统按统一基础档案和独立面积概况计算八项字段。
4. 用户点击导出，生成当前筛选全部结果的 `学校建筑统计.xlsx`。
5. 用户进入建筑或操场管理，筛选学校并只读查看基础信息和扩展档案。

## 5.5 操作日志生成与查询

1. 学校端成功保存业务数据后，系统按第 4.8 节动作口径生成一条规范化日志；附件批量上传按文件逐条生成。
2. 日志记录操作对象和来源快照后独立持久化，不依赖业务对象继续存在。
3. 学校端操作日志仅读取本校记录；教育局端操作日志读取管理范围内全部学校记录。
4. 日志按操作时间倒序排列，并使用与其他业务列表一致的连续序号及分页规则。

## 5.6 跨端同步与重置

1. 学校端保存建筑或操场后立即写入统一 localStorage。
2. 同一页面切换到教育局端时重新读取当前数据；不同标签页通过刷新读取。
3. 一键重置恢复预置建筑、操场和扩展数据，学校面积恢复未登记；运行时日志清除后仅恢复 3 条默认示例，并写入演示场景抑制标记，避免重置后自动再次生成 28 条日志。

# 6. 异常场景与边界条件

| 场景 | 处理规则 |
|---|---|
| 学校面积为空、为负数或超过两位小数 | 阻止保存并显示错误 |
| 学校面积分项之和与整体面积不一致 | 显示差额提示，允许保存 |
| 建筑或操场名称为空、长度不合法或同校重名 | 阻止保存 |
| 面积小于等于 0或超过两位小数 | 阻止保存 |
| 年份超出 1800—当前年份后一年的范围 | 阻止保存 |
| 鉴定日期、维修时间或改造日期不是合法日期 | 阻止保存并提示重新选择 |
| 维修记录未选择保修期限 | 阻止保存并提示选择固定期限 |
| 历史维修记录缺少或无法识别保修期限 | 展示“已维修”，保留原记录且不执行破坏性迁移 |
| 建筑层数不是 1—199 整数 | 阻止保存 |
| 鉴定等级超过 20 个字符 | 阻止保存 |
| 地面材质为“其他”但未填写材质名称 | 阻止保存模块 |
| 场地模块分类数量字段不是有效整数 | 阻止保存模块 |
| 模块面积合计与操场总面积不一致 | 允许保存，不展示差额说明 |
| 删除场地模块 | 二次确认；同步删除其内部改造记录并写入模拟日志 |
| 删除专项设施 | 二次确认；同步删除其内部维修记录并更新列表 |
| 删除器材信息 | 二次确认；确认后从当前操场移除并写入模拟日志，取消则不改变数据 |
| 专项设施或场地模块筛选无结果 | 显示空状态和清空筛选入口 |
| 六类列表筛选、重置筛选、切换学校或进入新档案详情 | 对应列表回到第 1 页，其他列表分页状态不变 |
| 六类列表为单页或零数据 | 仍显示“共 N 条”和完整分页组件，上一页、下一页按边界禁用 |
| 每页条数切换 | 仅接受 10、20、50、100；切换后回到第 1 页，无效值按默认 10 条处理 |
| 新增、删除或数据变化导致页码越界 | 自动修正到最后一个有效页；零数据时页码为第 1 页 |
| 学校统计筛选无结果 | 显示空状态并禁用导出 |
| 学校统计页码越界 | 修正到最后一个有效页 |
| Excel 生成失败 | 提示“导出失败，请重试”，不修改业务数据 |
| 教育局用户尝试写操作 | 页面不提供写入入口 |
| localStorage 缺失 | 使用预置场景或未登记空状态 |
| 旧户外草坪或操场级改造数据 | 执行幂等迁移，避免重复生成模块 |
| 成功保存单条业务变更 | 仅新增一条与动作、对象和业务来源对应的操作日志 |
| 批量上传 N 个附件 | 业务保存成功后新增 N 条“上传建筑附件”或“上传操场附件”日志 |
| 删除建筑、专项设施、场地模块、器材或附件 | 删除日志独立保留，且对象名称、所属学校、上级场地和来源键保持正确 |
| 删除父对象引起子数据级联清理 | 仅记录父对象删除，不为每条被清理的子数据生成日志 |
| 校验失败或取消删除 | 业务数据不变，不生成操作日志 |
| 查看、筛选、翻页、详情、附件预览、下载或统计导出 | 不生成操作日志 |
| 统一日志键首次不存在 | 迁移旧学校面积日志、旧操场扩展日志和 3 条默认示例并写入一次 |
| 统一日志键已存在 | 直接读取统一日志，不重复迁移旧日志 |
| 一次性演示场景标记不存在 | 按真实业务保存链路执行 28 次指定变更；全部成功后写入场景标记 |
| 一次性演示场景已完成 | 刷新仅读取已持久化业务数据和日志，不重复生成 |
| 一键重置完成 | 恢复原有 3 条默认日志并写入场景抑制标记，不自动重建 28 条日志 |
| 历史通用附件日志可识别所属场地 | 原位更新为建筑附件或操场附件动作，不新增日志且刷新后不重复变更 |
| 历史通用附件日志无法识别所属场地 | 保留“上传附件／删除附件”，不得默认归入建筑或操场 |

# 7. 数据口径与埋点需求

## 7.1 数据与统计口径

| 数据 | 存储或计算口径 |
|---|---|
| 建筑、操场基础档案 | `edu-prototype-v1.1:education-venue-records-v1` |
| 学校面积概况 | `edu-prototype-v1.1:education-school-area-profiles-v2` |
| 专项设施与维修记录 | `edu-prototype-v1.1:education-building-facilities-v6` |
| 场地模块、模块改造记录和器材 | `edu-prototype-v1.1:education-playground-records-v1` |
| 附件 | `edu-prototype-v1.1:education-venue-attachments-v1` |
| 汇总操作日志 | `edu-prototype-v1.1:education-venue-audit-logs-v1` |
| 一次性日志演示场景标记 | `edu-prototype-v1.1:education-venue-audit-demo-scenario-v1` |
| 建筑/操场数量 | 对应学校、对应类型的现存基础档案条目数 |
| 建筑/操场总面积 | 对应学校、对应类型的现存档案 `area` 之和 |
| 场地模块面积 | 模块自身独立填报，不反推操场总面积 |
| 更新时间 | 基础档案或扩展数据发生对应变更时生成的客户端演示时间 |
| 扩展档案添加时间 | 专项设施或场地模块首次新增时生成；旧数据迁移时使用原记录可用时间或所属档案更新时间补齐 |
| 六类业务列表分页状态 | 仅保存在页面运行时；默认每页 10 条，可选 10、20、50、100 条；刷新后恢复默认，不写入 localStorage |

## 7.2 埋点需求

当前原型以统一操作日志替代正式审计埋点。日志仅在业务数据保存成功后生成；页面进入、筛选、翻页、详情查看、附件预览、下载、导出、校验失败和取消操作不生成。正式系统的访问审计、真实 IP、服务端事务、防篡改及采集平台不在当前版本范围内。

# 8. 风险、依赖与限制

- 数据仅保存在同一浏览器 localStorage，不支持跨设备或跨浏览器同步。
- 不监听跨标签页实时变化；刷新或切换菜单后读取最新数据。
- 教育局只读和学校数据范围为前端演示约束，不构成生产级权限控制。
- XLSX 由前端原生 JavaScript 离线生成，不包含服务端文件、导出记录或审计。
- 附件不保存二进制，刷新后临时预览地址不保证可继续使用。
- 操作日志保存在同一浏览器 localStorage，不具备服务端事务、防篡改、真实 IP 或生产级审计能力。
- 操场模块面积不等于测绘面积，不作为正式空间统计依据。
- 页面字段变化必须同步本 PRD、产品需求建筑管理章节、页面内 PRD和发布断言。

# 9. 验收标准

## 9.1 学校端

- 建筑管理展示独立学校面积概况，默认无数据，可单独编辑并产生差额提示和操作日志。
- 建筑、操场新增、编辑、删除后刷新仍保留，且不会相互修改独立面积数据。
- 建筑、操场主列表和操作日志列表首列展示跨页连续序号，右下角分页组件在单页、零数据及多页场景下均正确展示。
- 建筑详情可维护八类专项设施、维修记录和附件。
- 专项设施以表格展示规定公共字段，维修状态紧跟当前状态并按最新维修日期和保修期限实时计算；类型、名称、状态组合筛选及重置正确；学校端删除需二次确认，教育局端仅可查看。
- 操场详情标签为基础信息、场地模块、器材信息、附件资料，不存在操场级独立改造记录标签。
- 器材信息列表序号跨页连续展示，分页后查看、编辑和删除仍作用于正确器材记录；查看以与编辑弹窗同尺寸的纯只读弹窗呈现，标题下无说明文字且底部仅有“关闭”按钮；学校端列表支持直接编辑和二次确认删除；教育局端仅可查看。
- 同一操场可新增多个同类型模块；“其他”模块不显示自定义类型名称。
- 模块改造记录归属于具体模块，删除模块同步移除其改造记录。
- 场地模块以表格展示规定公共字段，类型、名称、状态组合筛选及重置正确，筛选结果序号跨页连续，分页后操作仍定位正确记录。
- 建筑、操场、操作日志、专项设施、场地模块和器材信息六类列表默认每页 10 条，可切换 10、20、50、100 条；第 2 页首条序号分别为 11、21、51、101，切回 10 条后序号连续。
- 六类列表筛选及重置后回到第 1 页；删除最后一页记录后自动回退有效页；各列表分页状态相互独立且刷新后恢复默认每页 10 条。
- 建设、建造及最近改造年份均使用年份下拉，维修时间和改造日期使用日期选择器，保修期限只能选择规定的八个选项。

## 9.2 教育局端

- 菜单中“学校统计”位于“建筑管理”上方，默认页面仍为建筑管理。
- 学校统计固定展示八列，字段来源和计算结果符合第 4.7 节。
- 每页 10 所学校，筛选、翻页、空状态和页码修正正确。
- 导出包含当前筛选后的全部结果，文件名、工作表名、数值格式和空值处理正确。
- 教育局建筑、操场页面不显示学校面积概况和任何新增、编辑、删除入口。
- 教育局建筑、操场、专项设施、场地模块和器材信息列表使用与学校端一致的序号与分页规则，且只读限制不受影响。
- 学校端变更后，教育局刷新或切换页面可读取最新数据。
- 教育局端操作日志展示管理范围内跨学校记录，学校端仅展示本校记录。
